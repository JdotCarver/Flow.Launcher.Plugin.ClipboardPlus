# README.md — Synthetic performance baseline

Run on Windows with .NET 9: `dotnet run --project tools/performance-baseline/PerformanceBaseline.csproj -c Release`.
The program uses generated text and pixels and temporary SQLite databases; it does not access the real clipboard or plugin data. It warms each scenario once and reports five repetitions, process-wide managed allocation and a working-set snapshot. SQLite figures include database creation, insertion, read, closing and deletion; they are not startup timings. The GC scenario is isolated, not end-to-end copy latency. Bitmap encoding is synthetic. Results depend on machine load, disk, runtime, and ordering; compare runs on the same machine and do not interpret working set as Flow Launcher's memory consumption. This harness does not exercise fuzzy search, the Flow Launcher UI, live clipboard events or real startup; those require separate integration measurement.

Additional scenarios separate image hashing by image entropy, and prepare temporary databases outside the timed restore loop before reopening and materializing their records. The live-text measurement reports the managed heap delta after forced collections while retaining records; it is not a leak test or an estimate of native image memory. The database restore scenario excludes the plugin's initialization, expiration cleanup, UI, and Windows history synchronization. No scenario invokes the real Flow Launcher fuzzy matcher, clipboard monitor, or UI. These gaps must be addressed before ranking those paths.

The integration scenarios call the actual plugin query and record-add methods using generated records, a synthetic host and an in-memory record list. They do not initialize the plugin, start a clipboard monitor, open user settings or use the real clipboard. The host's simple substring matcher is deliberately NOT Flow Launcher's fuzzy matcher; query numbers include plugin traversal and result creation but cannot establish real fuzzy-matching cost or ranking. Cancellation coverage checks only a pre-cancelled query. Record-add timing excludes the clipboard event and data extraction, and includes the plugin's forced collections. Private-field access makes this an implementation-coupled diagnostic, not a stable plugin API test.
